0一句话定义

MyOS 不是待办清单，也不是笔记软件，而是一个人的长期成长数据资产系统。

核心命题：一次行动，产生多个结果。

Git Commit
  ↓
项目进度  →  作品集  →  日报  →  月度复盘  →  年度成长档案

1设计原则

这一版最重要的事情不是「加功能」，而是把边界立死，否则会变成一个什么都想装、最后什么都不用的系统。

编号原则说明
P1不再增加目标用户已有足够方向，V1 只做「让已存在的方向持续发生」的系统，不新增学习目标
P2记录优先于规划先让系统如实记录真实行动，再谈 AI 分析和规划。没有数据的智能都是空谈
P3减法优先每个功能都必须回答：「不做它，核心闭环会断吗？」答案是否，就不做
P4AI 是贯穿层，不是独立页面AI 能力嵌入今日/学习/输出/项目/复盘各处，不做孤立的「聊天页面」
P5只记录，不替用户决策财务模块只做记录、统计、提醒、复盘；投资决策绝不自动执行
P6写下来 > 做完美内容输出不追求爆款，只追求留下痕迹。系统设计要降低「写」的门槛
P7数据属于用户所有数据本地 PostgreSQL，可随时导出，不锁定

2双维度切分（关键概念澄清）

设计资料中出现了两套维度，必须分工明确，否则会互相打架。

2.1 两套维度

维度内容用途
7 大系统
内容视角		 AI 能力 / 技术能力 / 内容能力 / 英语与信息 / 身体 / 财务 / 人际 首页水位条的数据源；回答「今天 7 个系统分别有没有向前走一点」
6 大模块
功能视角		 今日 / 学习 / 输出 / 项目 / 财务 / 复盘 侧边栏导航结构；回答「我要去哪里操作」
分工约定（V1 强制）：6 模块做导航，7 系统做首页水位。 侧边栏只放 6 个入口，不为 7 个系统各开一个页面（太重，用户会迷路）。

4.3 能力等级（Lv）计算规则

V1 先用简单累计值分档，不做花哨算法。

系统依据分档（示例）
AI 能力AI 类学习累计分钟数每 600 分钟 +1 Lv
编程编程类学习 + 已完成项目数每 600 分钟 +1 Lv，每完成项目 +1 Lv
英语英语类学习累计分钟每 600 分钟 +1 Lv
内容创作已发布内容数每 10 篇 +1 Lv
身体运动打卡次数每 20 次 +1 Lv
财务连续记账月数每 3 个月 +1 Lv

分档阈值集中在后端一个 LevelRule 配置类里，方便后续调参。

5.2 新增表

habit_log —— 每日习惯打点（7 系统水位的数据源）

CREATE TABLE IF NOT EXISTS habit_log (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES my_user(id),
  log_date DATE NOT NULL,
  system_code VARCHAR(32) NOT NULL,    -- AI / TECH / CONTENT / ENGLISH / BODY / FINANCE / SOCIAL
  metric_value INT NOT NULL DEFAULT 0, -- 分钟数或次数
  target_value INT,                    -- 当时的目标值，便于回溯
  done BOOLEAN NOT NULL DEFAULT FALSE, -- 是否达标
  note VARCHAR(500),
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (user_id, log_date, system_code)
);
CREATE INDEX IF NOT EXISTS idx_habit_user_date ON habit_log(user_id, log_date);

project_log —— 项目开发日志（「一次行动产生多个结果」的落点）

CREATE TABLE IF NOT EXISTS project_log (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES my_user(id),
  project_id BIGINT NOT NULL REFERENCES project(id),
  log_date DATE NOT NULL,
  content TEXT NOT NULL,
  commit_ref VARCHAR(120),
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

finance_record —— 记账流水

CREATE TABLE IF NOT EXISTS finance_record (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES my_user(id),
  record_date DATE NOT NULL,
  record_type VARCHAR(16) NOT NULL,    -- INCOME / EXPENSE
  category VARCHAR(64),
  amount NUMERIC(14,2) NOT NULL,
  currency VARCHAR(8) NOT NULL DEFAULT 'CNY',
  note VARCHAR(500),
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

asset_snapshot —— 资产配置快照（按月）

CREATE TABLE IF NOT EXISTS asset_snapshot (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES my_user(id),
  snapshot_month DATE NOT NULL,        -- 每月 1 日
  cash NUMERIC(14,2) NOT NULL DEFAULT 0,
  cny_assets NUMERIC(14,2) NOT NULL DEFAULT 0,
  usd_assets NUMERIC(14,2) NOT NULL DEFAULT 0,
  other_assets NUMERIC(14,2) NOT NULL DEFAULT 0,
  note VARCHAR(500),
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (user_id, snapshot_month)
);

6模块详细需求

6.1 ① 今日 Today

功能优先级说明
今日任务列表P0 已有已实现，保留
今日习惯打点P0 新增7 系统各一行，支持填分钟数 / 打勾，一键保存
今日 AI 助手四入口P0 新增和 AI 讨论 / 总结今天 / 生成日报 / 复盘今天

习惯打点交互：一屏 7 行，每行「系统名 + 数值输入 + 达标勾选」，底部「保存今日打点」。已打过点的当天直接回显。

6.2 ② 学习 Learning

功能优先级说明
五段式学习记录P0 已有原始资料→理解→实践→结论，保留
学习记录列表 + 筛选P1按系统 / 时间筛选
知识库沉淀P1knowledge_item 接入（V1.1）

6.3 ③ 输出 Content

功能优先级说明
内容记录（草稿→发布）P0 已有保留
输出打卡日历P1 新增月度格子图，一眼看到「哪天没写」
发布状态流转P1DRAFT → PUBLISHED，自动回填 published_at

6.4 ④ 项目 Projects

功能优先级说明
项目列表（进度条）P0 已有保留
项目详情页P0 新增简介 / 解决的问题 / 技术栈 / GitHub / Demo / 截图 / 开发过程 / 问题 / 方案 / 成果
开发日志录入P1 新增project_log，与日报打通
Portfolio 作品集视图P1 新增按年月归档已完成项目，可对外展示

6.5 ⑤ 财务 Finance（全新）

三个层次分开做，不要混在一个页面：

① 现金流    收入 - 支出 = 结余
② 储蓄率    结余 / 收入
③ 资产配置  现金 / 人民币资产 / 美元资产 / 其他
功能优先级说明
记账（收入/支出）P0流水列表 + 快速录入
月度储蓄率P0自动计算，可设目标（如 30%）
资产快照P1按月填一次，展示配置占比
红线（对应原则 P5）：财务模块只做记录、统计、提醒、复盘。绝不接入自动交易、绝不替用户做投资决策、绝不给具体买卖建议。

6.6 ⑥ 复盘 Review（全新，但表已存在）

功能优先级说明
日复盘P0今天做了什么 / 收获 / 浪费的时间 / 明天重点
周复盘P0本周四件事：报告 / 整理 / 推进 / 复盘
月复盘P0项目完成情况 + 内容/习惯完成率 + AI 总结
年度成长档案P1 特色全年数据汇总 + AI 生成《年度成长报告》

年度成长档案字段（用户明确要求）：

365 天
内容输出 XX 篇 / 英语学习 XX 小时 / 运动 XX 次
行业报告 XX 份 / 完成项目 XX 个
AI 使用 X 种模型 / 作品集 XX 个
储蓄率 XX% / 认识新朋友 XX 人

然后 AI 自动生成：
这一年做了什么 → 获得什么能力 → 完成什么项目
→ 哪些目标没完成 → 哪些习惯坚持了
→ 哪些事浪费时间 → 下一年调整什么

7AI 能力设计（贯穿层）

7.1 定位

AI 不是第 7 个模块，而是贯穿 6 模块的底层能力（对应原则 P4）。

7.2 V1 AI 功能清单

功能位置输入输出
总结今天今日今日任务 + 打点 + 学习记录一段总结文字
生成日报今日同上结构化日报（可复制到内容模块）
复盘今天今日今日数据引导式复盘问答
月度总结复盘本月全量数据月复盘初稿
年度成长报告复盘全年数据长文报告

7.3 技术形态

  • 后端新增 ai 包，提供 AiGateway 接口，V1 先对接一个模型（避免过早抽象）。
  • 前端不做独立聊天页，只做场景化入口按钮。
  • API Key 存后端环境变量，绝不下发到前端。
  • 所有 AI 调用先落库（review.ai_summary 字段已存在），支持用户编辑后保存。

7.4 使用哲学（写入产品文案）

追求的不是「用更多 Token」，而是让 AI 成为思考伙伴。

正确姿势：提出想法 → AI 质疑 → 你修改 → AI 再质疑 → 形成方案 → 执行。

8版本边界（明确砍掉什么）

8.1 V1.0 必做（Definition of Done）

  1. 首页成长 Dashboard 完整实现（§4 全部区块）
  2. 今日习惯打点（7 系统）
  3. 项目详情页 + Portfolio 视图
  4. 财务：记账 + 储蓄率
  5. 复盘：日 / 周 / 月
  6. AI：至少「生成日报」一个场景打通
  7. goal 表启用，接通「年→月→周→今日」

8.2 V1.0 坚决不做（明确砍掉）

不做原因
知识库 RAG / 向量检索数据量还太小，做了没用（P2）
MCP / Agent 自动执行过早引入复杂度（P3）
GitHub 自动同步手动记录已够用，自动同步是 V2
多用户 / 社交 / 分享个人工具，不需要（P3）
移动 AppWeb 响应式已够（P3）
自动交易 / 投资建议触碰原则红线（P5）
独立 AI 聊天页违反原则 P4
花哨的等级 / 成就动画先有数据，再谈激励
第三方平台数据抓取合规与维护成本高

8.3 后续版本规划

版本主题

附录 B：一次行动产生多个结果（核心闭环）

用户完成一个动作
  ↓
① 写入事实数据（task / habit_log / project_log / learning_record）
  ↓
② 更新聚合视图（首页水位 / 能力 Lv / 本月进度）
  ↓
③ 生成可复用产出（日报 / 周报 / Portfolio 条目 / 内容草稿）
  ↓
④ 进入复盘（月复盘 / 年度成长档案）
这条链路是 MyOS 与普通待办软件的根本区别：普通软件只做 ①，MyOS 要做 ①→④。
